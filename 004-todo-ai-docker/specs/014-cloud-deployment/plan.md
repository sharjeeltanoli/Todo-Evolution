# Implementation Plan: Phase V Part C - Cloud Deployment

**Branch**: `014-cloud-deployment` | **Date**: 2026-02-08 | **Spec**: [specs/014-cloud-deployment/spec.md](spec.md)

## Summary
The goal is to migrate the Todo application from a local Minikube environment to a production-grade cloud infrastructure. This involves setting up a DigitalOcean Kubernetes (DOKS) cluster, integrating Redpanda Cloud for event streaming, and establishing an automated CI/CD pipeline via GitHub Actions. The deployment will focus on high availability, security (secrets management), and seamless integration with the existing Neon PostgreSQL database.

## Technical Context

**Language/Version**: Python 3.13+, TypeScript 5.x+, Node.js 20+
**Primary Dependencies**: Next.js 16.1+, FastAPI, SQLModel, Dapr, Helm, Docker
**Storage**: Neon Serverless PostgreSQL (External), Redpanda Cloud (Kafka Serverless)
**Testing**: pytest (Backend), Jest (Frontend), GitHub Actions (CI)
**Target Platform**: DigitalOcean Kubernetes (DOKS)
**Project Type**: Full-stack Web (Microservices)
**Performance Goals**: < 10min deploy time, 99.9% availability, < 200ms API response
**Constraints**: $200 DigitalOcean credit, Redpanda Cloud Free Tier, Zero downtime deployments
**Scale/Scope**: 4 Microservices (Frontend, Backend, Notification, Recurring Task), 2+ replicas each

## Phase 0: Outline & Research

### Research Tasks
- **DOKS Cluster Setup**: Best practices for droplet sizes (Basic vs General Purpose) within the $200 credit limit.

- **GitHub Actions to DOKS**: Securely managing kubeconfig and DigitalOcean API tokens in GitHub Secrets.
- **LoadBalancer Configuration**: Configuring the DigitalOcean LoadBalancer via Helm values for the `todo-frontend`.
